## What Was Built

### 1. Live Stats System
- Real-time metrics fetched from `https://dns.thecutline.org/stats.json`
- Per-site data (EWR and LAX) including:
  - Health status (healthy/unhealthy)
  - Distinct IPs in last 7 days
  - Latency p50 and p95 (last 24 hours)
- **Fail-closed behavior**: Shows em-dash (—) if collector is down
- **NEVER shows fake data** like "847 IPs" or "2.4 Gbps"

### 2. Daily Aggregate History
- Append-only JSONL format at `/var/cutline/stats/history.jsonl`
- One entry per day per site
- Contains only dates and aggregate integers (no IPs)
- Public and long-term

### 3. Privacy-Compliant IP Tracking
- Source IPs stored for exactly 7 days
- Automatic pruning on every collection run
- Query names **NEVER** stored
- IP log at `/var/cutline/stats/ip_log.txt` (never committed to git)
- `.gitignore` updated to exclude all IP logs and raw data

### 4. Latency Specification
- Added to `/spec` page under "Resolver Performance Metrics"
- **Definition**: Query received → answer sent (resolver processing time only)
- **Excludes**: Last-mile latency, browser overhead, client OS delays
- **Metrics**: p50 (median) and p95 (95th percentile)
- **Window**: Last 24 hours
- **Granularity**: Per resolver site (EWR and LAX separate)

### 5. Collector Infrastructure
Located in `resolver/collector/`:
- `collect-stats.sh` - Main collector (queries Prometheus, maintains IP log, generates JSON)
- `query-logger.sh` - Feeds IPs from DNS logs (query names excluded)
- `nginx-stats.conf` - Serves stats with CORS for thecutline.org
- `README.md` - Complete deployment documentation
- `schemas/` - JSON schemas for validation

### 6. Website Changes

  - ✅ Removed "847 IPs" and "2.4 Gbps" fake numbers
  - ✅ Removed StevenBlack branding from stats page

  - ✅ Removed overlay URL refresh instructions (stale copy)
  - ✅ Added clear privacy statement

  - ✅ Client-side fetch with 60s refresh
- **Spec page** updated with latency metric definition

### 7. Blocky Configuration
- Enabled Prometheus metrics on port 4000
- Exposes `blocky_request_duration_ms` for latency calculation

## What's NOT Included (Deployment Required)

The following must be done manually after merge:

1. **Deploy to VMs**:
   - Copy collector scripts to `/opt/cutline/collector/` on both VMs
   - Set `CUTLINE_SITE=ewr` on EWR VM (64.176.200.99)
   - Set `CUTLINE_SITE=lax` on LAX VM (149.28.79.49)
   - Create `/var/cutline/stats/` directory
   - Set up cron job for collection (every 5 minutes)

2. **Update Blocky**:
   - Deploy new `resolver/config.yml` with Prometheus enabled
   - Restart Blocky containers on both VMs

3. **Configure Nginx**:
   - Include `nginx-stats.conf` snippet in dns.thecutline.org vhost
   - Reload nginx

See `resolver/collector/README.md` for detailed step-by-step instructions.

## Architecture Flow

```
Resolver VM (EWR/LAX)
  │
  ├─ Blocky (:53) ──> Prometheus metrics (:4000)
  │                            │
  │                            v
  ├─ collect-stats.sh (cron */5 min)
  │    │
  │    ├─ Query Prometheus → latency metrics
  │    ├─ Count IPs → /var/cutline/stats/ip_log.txt (7d prune)
  │    ├─ Generate → /var/cutline/stats/stats.json
  │    └─ Append → /var/cutline/stats/history.jsonl
  │
  └─ Nginx
       └─ Serve stats.json (CORS: thecutline.org)

thecutline.org/stats (client-side)
  └─ Fetch from both resolvers
       └─ Display or show em-dash (fail-closed)
```
